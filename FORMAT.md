# Разметка статьи

Статья написана в markdown с несколькими расширениями, которые понимает
сборщик этого репозитория:
нумерация, перекрёстные ссылки, формулы, tikz-рисунки. Ниже — весь набор
конструкций, встречающихся в тексте.

## Frontmatter

YAML-блок в начале файла, ключ `ispras_templates`, — всё, что в свёрстанном
документе живёт вне основного текста:

- `header_ru` / `header_en` — название статьи;
- `authors` — имя, ORCID, email, справка об авторе и список организаций
  (по идентификаторам из `organizations`) на двух языках;
- `organizations` — идентификатор и полное название с адресом;
- `links` — список литературы: `id` (по нему ссылаются из текста) и
  `description` — библиографическая запись целиком;
- `abstract_ru` / `abstract_en`, `keywords_ru` / `keywords_en`;
- `for_citation_ru` / `for_citation_en` — запись для цитирования;
- `page_header_ru` / `page_header_en` — колонтитул, `@use_citation` берёт его из
  записи для цитирования;
- `acknowledgements_ru` / `acknowledgements_en` — благодарности, `@none` убирает
  раздел.

## Заголовки

```markdown
# Реализация {#chapt5}

## Общая структура {#sect:impl-overview}

### Стек активных узлов {#subsect:impl-runtime-stack}
```

Уровни `#`–`###` нумеруются автоматически и иерархически: «4», «4.1», «4.1.1».
Идентификатор в `{#…}` — цель для перекрёстных ссылок из текста.

`####` и `#####` — ненумерованные жирные врезки (аналог `\paragraph` в LaTeX),
ими размечены разборы примеров срабатываний и описания типов узлов.

## Перекрёстные ссылки

```markdown
см. раздел <span class=ref>sect:hierarchy</span>
предупреждение компилятора GCC <span class=cite>gcc-manual</span>
```

`class=ref` подставляет номер цели — раздела, рисунка, листинга, таблицы,
определения, утверждения, леммы, алгоритма. `class=cite` подставляет номер
источника из `links` во frontmatter.

Счётчики раздельные и определяются префиксом идентификатора: `fig:`, `lst:`,
`tab:` — подписи; `def:`, `stmt:`, `lem:`, `alg:` — theorem-окружения;
`chapt`, `sect:`, `subsect:`, `app:` — заголовки. Нумерация сквозная по всей
статье и следует порядку определений. Неизвестные и повторные метки вызывают
ошибку сборки.

## Формулы

Строчные — в обратных кавычках внутри `$`, блочные — `$$` на отдельных строках,
внутри обычный TeX без кавычек:

```markdown
Узлы $`a,b`$ _упорядочены_, если $`a\sbarrow b`$ или $`b\sbarrow a`$.

$$
\begin{aligned}
R_1&=\{(c,p)\mid(p,c)\in E\},\\
R_2&=\{(x,y)\mid\exists\,(u,v)\in\mathrm{SP},~x\in\mathcal{T}(u),~y\in\mathcal{T}(v)\}.
\end{aligned}
$$
```

Формулы рендерятся картинками с точным выравниванием по базовой линии — это
делает сборщик при сборке, отдельного шага не требуется.

Длинную формулу лучше делать блочной: строчная попадает в документ монолитной
картинкой, которую Word не переносит, и она вылезает за поле (ширина текстовой
колонки — 14 см).

## Рисунки

```markdown
![](figures/fig-final-architecture.png)
```

Путь считается относительно входного Markdown. Соседний файл с тем же именем и
расширением `.svg` вставляется как векторная версия рисунка. TikZ при сборке
запускается только с флагом `--figures`. Геометрия рисунков, включая
расположение и зазоры подрисунков «а»/«б», задана внутри самих tikz-исходников,
а не разметкой статьи. Исходники находятся в `figures/source/`.

## Листинги и таблицы

Листинг — блок кода с отступом в четыре пробела. Таблица — обычная
markdown-таблица с вертикальными чертами. Выравнивание столбцов задаётся
двоеточиями в строке-разделителе.

## Подписи

```markdown
<div class="img-caption">Рис. <span class=ref>fig:lca-depth</span>. Накопленное распределение высоты подъёма</div>
<div class="listing-caption">Листинг <span class=ref>lst:practice-example</span>. Пример программы с ошибкой</div>
<div class="table-caption">Табл. <span class=ref>tab:lca-depth</span>. Перцентили высоты подъёма</div>
```

Подпись рисунка идёт после маркера рисунка, подпись листинга — после кода,
подпись таблицы — перед таблицей. Внутри подписи работают `*курсив*`, `<em>`,
`<sub>`, `<sup>` и код в обратных кавычках (рендерится моноширинным).

## Theorem-окружения

Определения, утверждения, леммы и алгоритмы оформлены жирным зачином в начале
абзаца — как окружения `amsthm`:

```markdown
**Утверждение <span class=ref>stmt:lca-criterion</span>** (критерий упорядоченности). Пусть …
```

Конец доказательства помечается `<span class=qed></span>` — вплотную к
последнему символу абзаца, без пробела. Конвертер отбивает знак «□» к правому
краю табулятором. Границы доказательства нигде не размечены явно: они
содержательные, маркер просто закрывает последний абзац.

## Типографика

Неразрывные пробелы (U+00A0) в тексте расставлены намеренно — они пришли из `~`
в исходном LaTeX и держат вместе номера с единицами, инициалы, короткие
предлоги. Заменять их на обычные пробелы нельзя.

Тире — длинное («—») с неразрывным пробелом слева, чтобы оно не начинало строку.

Массовые правки пробелов и тире надёжнее делать скриптом: невидимые символы
легко потерять при ручном редактировании.
